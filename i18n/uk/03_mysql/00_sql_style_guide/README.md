# 00 Стиль написання SQL

> Translation / Переклад: [English](../../../../03_mysql/00_sql_style_guide/README.md)

Дотримуйтеся єдиного стилю в усіх SQL-скриптах цього репозиторію.

## Мета

Зробити SQL читабельним, придатним до рев'ю та готовим до продакшну з самого початку.

## Правила іменування

- Використовуйте `snake_case` для таблиць, стовпців, індексів і обмежень.
- Імена мають бути описовими (`service_order_id` замість `id2`).
- Аліаси — короткі та змістовні (`c` — для `customers`, `so` — для `service_orders`).

## Форматування запитів

- SQL-ключові слова великими літерами (`SELECT`, `FROM`, `JOIN`, `WHERE`).
- Один обраний стовпець на рядок для середніх/великих запитів.
- Кожен `JOIN` — окремим рядком із явним `ON`.
- Додавайте коментарі лише там, де бізнес-логіка не очевидна.

## Правила безпеки

- Ніколи не запускайте `UPDATE`/`DELETE` без `WHERE`, якщо це не свідомо.
- Перевіряйте деструктивні зміни спочатку за допомогою `SELECT`.
- Обгортайте багатокрокові операції запису у транзакції, де це доречно.

## Чек-ліст для рев'ю

- [ ] Запит має ясний намір і читабельну структуру
- [ ] З'єднання використовують правильні ключі без випадкових декартових добутків
- [ ] Предикати можуть використовувати наявні індекси, де це можливо
- [ ] Скрипт повторюваний або явно позначений як одноразовий

## Результат цього етапу

Спільний стиль SQL, що зменшує помилки та тертя під час рев'ю в усіх уроках.
