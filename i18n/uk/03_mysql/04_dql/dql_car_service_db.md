## Карта секцій та операторів (відповідає матеріалам курсу)

| Тема | Ідеї SQL |
|------|----------|
| **(а) `SELECT`** | Обрати стовпці або вирази; перейменувати через `AS`. |
| **(б) `FROM`** | З яких таблиць беруться рядки (`FROM customers`, далі — `JOIN`). |
| **(в) `WHERE`** | Фільтрувати рядки **до** групування. |
| **(г) `GROUP BY`** | Один результуючий рядок на групу; використовується з агрегатами. |
| **`NULL`** | Невідоме / відсутнє; перевіряти через `IS NULL`, `IS NOT NULL`; за потреби `COALESCE(col, default)`. |
| **`WHERE` + `AND`, `OR`, `IN`, `LIKE`, `IS`, `NOT`** | Поєднання предикатів; шаблони з `LIKE 'A%'`; множини з `IN (...)`; заперечення через `NOT` або `<>`. |
| **Агрегати** | `COUNT`, `SUM`, `AVG`, `MIN`, `MAX` — підсумок над багатьма рядками. |
| **`GROUP BY`** | Задати групи (напр., за `status`); агрегати працюють у межах групи. |
| **`HAVING`** | Фільтр **груп** (після `GROUP BY`); умови з агрегатами. |
| **`ORDER BY`** | Сортування (`ASC` / `DESC`). |
| **`DISTINCT`** | Видалити дублікати значень у вказаних виразах. |
| **`LIMIT`** | Повернути не більше *N* рядків. |
| **`LIMIT … OFFSET …`** | Пропустити *OFFSET* рядків, потім узяти *LIMIT* (пагінація). |

## Вправа 1 — `SELECT … FROM …`

### Контекст

CRM-форма підказує касиру клієнтів, коли той починає вводити прізвище. Потрібен тонкий, упорядкований зріз — лише ті стовпці, які UI справді показує.

### Чого ви навчитеся

- Обирати конкретні стовпці замість `SELECT *`.
- Обмежувати скан через `WHERE id BETWEEN …`.
- Обмежувати розмір вибірки через `LIMIT`.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `customers` | `id`, `first_name`, `last_name`, `email` |

### Завдання

Повернути `id`, `first_name`, `last_name`, `email` для клієнтів з `id` від 1 до 200. Обмежити до 20 рядків.

### Очікуваний результат (реальні рядки з дампу)

```text
+----+------------+------------+------------------------+
| id | first_name | last_name  | email                  |
+----+------------+------------+------------------------+
|  1 | Name_1     | Surname_1  | customer1@example.com  |
|  2 | Name_2     | Surname_2  | customer2@example.com  |
| ...|            |            |                        |
| 20 | Name_20    | Surname_20 | customer20@example.com |
+----+------------+------------+------------------------+
```

### Підказка

Потрібен лише `SELECT` з таблиці `customers` з фільтром `BETWEEN` і `LIMIT`.

### Розв'язання

```sql
SELECT id,
       first_name,
       last_name,
       email
FROM customers
WHERE id BETWEEN 1 AND 200
LIMIT 20;
```

### Покрокове пояснення

1. **`SELECT id, first_name, ...`** перелічує потрібні стовпці — у продакшені ніколи не використовуйте `SELECT *`: це передає по мережі зайві дані.
2. **`FROM customers`** обирає таблицю.
3. **`WHERE id BETWEEN 1 AND 200`** — інклюзивний діапазон (`1 <= id <= 200`). Без нього MySQL прочитав би усі 100 000 клієнтів.
4. **`LIMIT 20`** обмежує вивід. Він не сортує — якщо потрібен стабільний топ-N, додайте `ORDER BY` (див. Вправу 8).

## Вправа 2 — `NULL` та `COALESCE`

### Контекст

Адміністратор хоче видрукувати конверти лише для клієнтів, **у яких є телефон** (зателефонуємо щодо запису), а у SMS-звіті відобразити заглушку `'no phone'` для решти. Обидва сценарії потребують `NULL`-безпечного виразу.

### Чого ви навчитеся

- Різницю між `IS NULL` / `IS NOT NULL` та `= NULL` (яке ніколи не спрацює!).
- `COALESCE(col, default)` як замінник.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `customers` | `id`, `first_name`, `last_name`, `phone` |

### Завдання

Показати перших 15 клієнтів (`id BETWEEN 1 AND 300`), у яких `phone IS NOT NULL`. Вивести як сам `phone`, так і `phone_display` через `COALESCE`, що підставляє `'no phone'` для відсутніх значень.

### Очікуваний результат (реальні рядки з дампу)

```text
+----+------------+------------+---------------+---------------+
| id | first_name | last_name  | phone         | phone_display |
+----+------------+------------+---------------+---------------+
|  1 | Name_1     | Surname_1  | +380500000001 | +380500000001 |
|  2 | Name_2     | Surname_2  | +380500000002 | +380500000002 |
| ...|            |            |               |               |
| 15 | Name_15    | Surname_15 | +380500000015 | +380500000015 |
+----+------------+------------+---------------+---------------+
```

### Підказка

`phone IS NOT NULL` для фільтра; `COALESCE(phone, 'no phone')` для відображення.

### Розв'язання

```sql
SELECT id,
       first_name,
       last_name,
       phone,
       COALESCE(phone, 'no phone') AS phone_display
FROM customers
WHERE id BETWEEN 1 AND 300
  AND phone IS NOT NULL
LIMIT 15;
```

### Покрокове пояснення

1. **`COALESCE(phone, 'no phone')`** повертає перший не-`NULL` аргумент. Використовуйте її, коли треба залишити рядок, але приховати відсутнє значення.
2. **`WHERE … AND phone IS NOT NULL`** фільтрує спеціальним оператором перевірки на `NULL`. `phone = NULL` не спрацює, бо `NULL = NULL` повертає `NULL` (тобто «невідомо»), а не `TRUE`.
3. Типовий баг: `WHERE phone <> NULL` — та ж пастка, предикат стає `NULL`, рядок пропадає. Завжди використовуйте `IS NULL` / `IS NOT NULL`.

## Вправа 3 — `WHERE` (один предикат)

### Контекст

Менеджеру сервісу потрібен швидкий перелік **закритих (completed)** замовлень для звірки сьогоднішніх інвойсів.

### Чого ви навчитеся

- Фільтрації одним предикатом-рівністю.
- Поєднанню фільтра з діапазоном `id` для швидкості.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `work_orders` | `id`, `vehicle_id`, `status`, `total_cost` |

### Завдання

Вивести `id`, `vehicle_id`, `status`, `total_cost` для замовлень зі `status = 'completed'` і `id BETWEEN 1 AND 5000`. Обмежити 25 рядками.

### Очікуваний результат (реальні рядки з дампу)

```text
+-----+------------+-----------+------------+
| id  | vehicle_id | status    | total_cost |
+-----+------------+-----------+------------+
|   4 |          4 | completed |     500.40 |
|   9 |          9 | completed |     500.90 |
|  14 |         14 | completed |     501.40 |
| ... |            |           |            |
| 124 |        124 | completed |     512.40 |
+-----+------------+-----------+------------+
```

### Підказка

Один `=` предикат на `status` плюс діапазон `id`.

### Розв'язання

```sql
SELECT id,
       vehicle_id,
       status,
       total_cost
FROM work_orders
WHERE status = 'completed'
  AND id BETWEEN 1 AND 5000
LIMIT 25;
```

### Покрокове пояснення

1. **`status = 'completed'`** — звичайна рівність. Рядки в лапках; для `varchar` з `utf8mb4_0900_ai_ci` MySQL не чутливий до регістру, тож `'COMPLETED'` теж спрацює — але дотримуйтесь канонічної форми.
2. **`AND id BETWEEN …`** звужує скан; без нього MySQL читав би всі 100 000 замовлень.
3. **Без `ORDER BY`** — рядки повертаються в порядку, у якому їх читає storage engine; тут це нормально, але для продакшен-звітів ніколи на це не покладайтесь.

## Вправа 4 — `WHERE` з `AND`, `OR`, `IN`, `LIKE`, `IS`, `NOT`

### Контекст

Три невеличких звіти, які адміністратор робить щоранку:

- (а) знайти клієнтів, чиє ім'я або прізвище збігається з шаблоном;
- (б) витягти замовлення, які **ще не закриті** (`new`, `in_progress` або `waiting_parts`);
- (в) знайти замовлення, у яких **є призначений механік** і вони **не скасовані**.

### Чого ви навчитеся

- Поєднувати предикати через `AND` / `OR`.
- Множини через `IN (...)`.
- Шаблони через `LIKE`.
- `IS NOT NULL` і `NOT` для булевих фільтрів.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `customers` | `id`, `first_name`, `last_name`, `email` |
| `work_orders` | `id`, `vehicle_id`, `assigned_mechanic_id`, `status`, `total_cost` |

### Завдання

Три незалежні запити:

1. Клієнти `id BETWEEN 1 AND 2000`, у яких `first_name LIKE 'Name_1%' OR 'Name_2%'` або `last_name LIKE 'Surname_1%'`. Limit 20.
2. Замовлення `id BETWEEN 1 AND 10000` зі `status IN ('new','in_progress','waiting_parts')`. Limit 25.
3. Замовлення `id BETWEEN 1 AND 5000` з `assigned_mechanic_id IS NOT NULL AND NOT (status = 'cancelled')`. Limit 25.

### Очікуваний результат (реальні рядки з дампу — запит 2)

```text
+----+------------+---------------+------------+
| id | vehicle_id | status        | total_cost |
+----+------------+---------------+------------+
|  1 |          1 | new           |     500.10 |
|  2 |          2 | in_progress   |     500.20 |
|  3 |          3 | waiting_parts |     500.30 |
|  6 |          6 | new           |     500.60 |
| ...|            |               |            |
+----+------------+---------------+------------+
```

### Підказка

- `IN (...)` замість `status = 'a' OR status = 'b' OR ...`.
- `LIKE 'Name_1%'` зловить `Name_1`, `Name_10`, …, `Name_19`, `Name_100`, ….
- `NOT (status = 'cancelled')` ідентичне `status <> 'cancelled'`; обидва варіанти валідні.

### Розв'язання

```sql
-- (1) Пошук за шаблонами імен
SELECT id, first_name, last_name, email
FROM customers
WHERE id BETWEEN 1 AND 2000
  AND (
        (first_name LIKE 'Name_1%' OR first_name LIKE 'Name_2%')
     OR last_name  LIKE 'Surname_1%'
  )
LIMIT 20;

-- (2) Належність до множини через IN
SELECT id, vehicle_id, status, total_cost
FROM work_orders
WHERE id BETWEEN 1 AND 10000
  AND status IN ('new', 'in_progress', 'waiting_parts')
LIMIT 25;

-- (3) IS NOT NULL у поєднанні з NOT
SELECT id, assigned_mechanic_id, status
FROM work_orders
WHERE id BETWEEN 1 AND 5000
  AND assigned_mechanic_id IS NOT NULL
  AND NOT (status = 'cancelled')
LIMIT 25;
```

### Покрокове пояснення

1. **Дужки мають значення.** У запиті (1) без внутрішніх `()` `AND` зв'язується сильніше за `OR`, і предикат непомітно змінює сенс — класичне джерело багів.
2. **`IN (...)`** — це скорочений запис `OR`-ланцюжка на одній колонці. Краще через читабельність і тому, що MySQL може оптимізувати у пошук по індексу.
3. **`LIKE 'A%'`** використовує `%` як wildcard на будь-яку кількість символів і `_` — на один. Літеральний `%` екранується `\%`.
4. **`IS NOT NULL`, не `<> NULL`.** Див. Вправу 2 — `<> NULL` повертає `NULL`, що відфільтровує рядок.

## Вправа 5 — Агрегати (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`)

### Контекст

Власник СТО хоче одноразовий зведений звіт економіки замовлень за статусами: скільки замовлень, на яку суму, середній чек, найдешевше і найдорожче.

### Чого ви навчитеся

- П'ять основних агрегатів в одному запиті.
- Чому агрегати вимагають або `GROUP BY`, або «без групування» (один результат-рядок).

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `work_orders` | `status`, `total_cost` |

### Завдання

Для `work_orders` з `id BETWEEN 1 AND 50000` повернути на кожен `status`: кількість, суму, середнє, мінімум і максимум `total_cost`. Сортувати за `status`.

### Очікуваний результат (реальні рядки з дампу)

```text
+---------------+-----------+-------------+-------------+----------+----------+
| status        | row_count | sum_cost    | avg_cost    | min_cost | max_cost |
+---------------+-----------+-------------+-------------+----------+----------+
| cancelled     |     10000 | 29997500.00 | 2999.750000 |   500.00 |  5499.50 |
| completed     |     10000 | 30001500.00 | 3000.150000 |   500.40 |  5499.90 |
| in_progress   |     10000 | 29999500.00 | 2999.950000 |   500.20 |  5499.70 |
| new           |     10000 | 29998500.00 | 2999.850000 |   500.10 |  5499.60 |
| waiting_parts |     10000 | 30000500.00 | 3000.050000 |   500.30 |  5499.80 |
+---------------+-----------+-------------+-------------+----------+----------+
```

### Підказка

`COUNT(*)`, `SUM(total_cost)`, `AVG(total_cost)`, `MIN(total_cost)`, `MAX(total_cost)`, групуємо за `status`.

### Розв'язання

```sql
SELECT status,
       COUNT(*)         AS row_count,
       SUM(total_cost)  AS sum_cost,
       AVG(total_cost)  AS avg_cost,
       MIN(total_cost)  AS min_cost,
       MAX(total_cost)  AS max_cost
FROM work_orders
WHERE id BETWEEN 1 AND 50000
GROUP BY status
ORDER BY status;
```

### Покрокове пояснення

1. **`COUNT(*)`** рахує рядки (зокрема ті, де є `NULL` у якійсь колонці). **`COUNT(col)`** рахує не-`NULL` значення `col` — використовуйте те, що відповідає питанню.
2. **`SUM`/`AVG`** ігнорують `NULL`. Якщо у групі всі значення `NULL`, обидва повертають `NULL` (а не `0`).
3. **`GROUP BY status`** має перелічувати кожен не-агрегатний стовпець із `SELECT`. MySQL з `ONLY_FULL_GROUP_BY` це жорстко перевіряє.
4. **`ORDER BY status`** сортує групи в алфавітному порядку. Без нього порядок груп невизначений.

## Вправа 6 — `GROUP BY` (кількість у категорії)

### Контекст

Віджет на дашборді «Воронка замовлень» — скільки замовлень зараз у кожному статусі.

### Чого ви навчитеся

- Простому `GROUP BY` з одним `COUNT(*)`.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `work_orders` | `status` |

### Завдання

Підрахувати рядки на кожен `status` для `id BETWEEN 1 AND 50000`. Сортувати за `status`.

### Очікуваний результат (реальні рядки з дампу)

```text
+---------------+----------+
| status        | how_many |
+---------------+----------+
| cancelled     |    10000 |
| completed     |    10000 |
| in_progress   |    10000 |
| new           |    10000 |
| waiting_parts |    10000 |
+---------------+----------+
```

### Підказка

`SELECT status, COUNT(*) FROM ... GROUP BY status`.

### Розв'язання

```sql
SELECT status,
       COUNT(*) AS how_many
FROM work_orders
WHERE id BETWEEN 1 AND 50000
GROUP BY status
ORDER BY status;
```

### Покрокове пояснення

1. **`GROUP BY status`** «склеює» всі рядки з однаковим `status` в одне відро.
2. **`COUNT(*)`** рахує рядки в кожному відрі. **Колонка з `GROUP BY` — єдина не-агрегатна, яку можна писати в `SELECT`.**
3. **`ORDER BY status`** — це **не** автоматично. Без нього MySQL може повернути відра у будь-якому порядку.

## Вправа 7 — `HAVING` (фільтр груп)

### Контекст

Менеджер хоче бачити лише такі статус-відра, що одночасно **великі** (>100 замовлень) та **з нормальною ціною** (середнє > 400) — щоб відсіяти шум.

### Чого ви навчитеся

- Різниці між `WHERE` (фільтрує **рядки**) і `HAVING` (фільтрує **групи**).
- Кільком умовам у `HAVING` на агрегатах.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `work_orders` | `status`, `total_cost` |

### Завдання

Для `id BETWEEN 1 AND 100000` згрупувати за `status`, залишити лише групи з `COUNT(*) >= 100 AND AVG(total_cost) > 400`. Сортувати за `avg_cost` спадно.

### Очікуваний результат (реальні рядки з дампу)

```text
+---------------+----------+-------------+
| status        | how_many | avg_cost    |
+---------------+----------+-------------+
| completed     |    20000 | 3000.150000 |
| waiting_parts |    20000 | 3000.050000 |
| in_progress   |    20000 | 2999.950000 |
| new           |    20000 | 2999.850000 |
| cancelled     |    20000 | 2999.750000 |
+---------------+----------+-------------+
```

### Підказка

У `HAVING` агрегати можна писати напряму (`COUNT(*)`, `AVG(total_cost)`).

### Розв'язання

```sql
SELECT status,
       COUNT(*)        AS how_many,
       AVG(total_cost) AS avg_cost
FROM work_orders
WHERE id BETWEEN 1 AND 100000
GROUP BY status
HAVING COUNT(*) >= 100
   AND AVG(total_cost) > 400
ORDER BY avg_cost DESC;
```

### Покрокове пояснення

1. **`WHERE` виконується до `GROUP BY`** — тому у ньому не можна писати агрегати.
2. **`HAVING` виконується після `GROUP BY`** — фільтрує групи за їхніми агрегатними значеннями.
3. **Логічний порядок виконання:** `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`.
4. Типова помилка: `WHERE COUNT(*) >= 100` — це синтаксична помилка в MySQL.

## Вправа 8 — `ORDER BY` (сортування)

### Контекст

Віджет «High-ticket» на дашборді менеджера: 30 найдорожчих замовлень за спаданням.

### Чого ви навчитеся

- `ORDER BY col DESC, col2 ASC` для стабільного багатоключового сортування.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `work_orders` | `id`, `total_cost`, `status` |

### Завдання

Для `id BETWEEN 1 AND 2000` сортувати за `total_cost DESC`, потім `id ASC`. Limit 30.

### Очікуваний результат (реальні рядки з дампу)

```text
+------+------------+---------------+
| id   | total_cost | status        |
+------+------------+---------------+
| 2000 |     700.00 | cancelled     |
| 1999 |     699.90 | completed     |
| 1998 |     699.80 | waiting_parts |
| 1997 |     699.70 | in_progress   |
| 1996 |     699.60 | new           |
| ...  |            |               |
+------+------------+---------------+
```

### Підказка

Двоключове `ORDER BY`. Другий ключ — для тай-брейкера і детермінованості.

### Розв'язання

```sql
SELECT id,
       total_cost,
       status
FROM work_orders
WHERE id BETWEEN 1 AND 2000
ORDER BY total_cost DESC, id ASC
LIMIT 30;
```

### Покрокове пояснення

1. **`ORDER BY total_cost DESC`** сортує за спаданням.
2. **`, id ASC`** — **тайбрейкер**: коли дві ціни рівні, менший `id` перший. Без нього порядок при однакових цінах не визначений і може змінитись між запусками.
3. **`LIMIT 30`** застосовується **після** сортування — саме так і працює «топ-N».

## Вправа 9 — `DISTINCT`

### Контекст

Два enum-подібних дропдауни в адмінці: список наявних статусів замовлень і список наявних брендів запчастин.

### Чого ви навчитеся

- `DISTINCT` прибирає дублікати по вказаних виразах.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `work_orders` | `status` |
| `parts` | `id`, `brand` |

### Завдання

Два незалежні запити:

1. Унікальні `status` з `work_orders` (`id BETWEEN 1 AND 20000`).
2. Унікальні `brand` з `parts` (`id BETWEEN 1 AND 5000`, `brand IS NOT NULL`).

### Очікуваний результат (реальні рядки з дампу — запит 1)

```text
+---------------+
| status        |
+---------------+
| cancelled     |
| completed     |
| in_progress   |
| new           |
| waiting_parts |
+---------------+
```

### Підказка

`SELECT DISTINCT col FROM ...`. Без агрегатів і `GROUP BY`.

### Розв'язання

```sql
SELECT DISTINCT status
FROM work_orders
WHERE id BETWEEN 1 AND 20000;

SELECT DISTINCT brand
FROM parts
WHERE id BETWEEN 1 AND 5000
  AND brand IS NOT NULL;
```

### Покрокове пояснення

1. **`DISTINCT`** убирає дублікати по **всьому набору обраних колонок**, а не по одній.
2. Для однієї колонки це еквівалентно `GROUP BY` без агрегатів — але `DISTINCT` зрозуміліший для наміру «дай унікальні значення».
3. **`brand IS NOT NULL`** у другому запиті: інакше `NULL` показався б як одне зі «значень».

## Вправа 10 — `LIMIT`

### Контекст

Швидкий preview-список 12 запчастин на головній сторінці складу.

### Чого ви навчитеся

- `LIMIT n` для обмеження виводу.
- Поєднанню `ORDER BY` + `LIMIT` для передбачуваних preview.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `parts` | `id`, `sku`, `name` |

### Завдання

Перші 12 рядків з `parts` з `id BETWEEN 1 AND 10000`, відсортовані за `id` зростанням.

### Очікуваний результат (реальні рядки з дампу)

```text
+----+--------------+---------+
| id | sku          | name    |
+----+--------------+---------+
|  1 | SKU-00000001 | Part_1  |
|  2 | SKU-00000002 | Part_2  |
| ...|              |         |
| 12 | SKU-00000012 | Part_12 |
+----+--------------+---------+
```

### Підказка

`ORDER BY id`, щоб «перші 12» було осмислено, потім `LIMIT 12`.

### Розв'язання

```sql
SELECT id,
       sku,
       name
FROM parts
WHERE id BETWEEN 1 AND 10000
ORDER BY id
LIMIT 12;
```

### Покрокове пояснення

1. **`LIMIT 12`** завжди застосовується після `ORDER BY`. Без `ORDER BY` поняття «перші 12» не визначене — MySQL може повернути будь-які 12.
2. **Від'ємний `LIMIT`** — синтаксична помилка. Щоб «пропустити» рядки, використовуйте `OFFSET` (Вправа 11).

## Вправа 11 — `LIMIT … OFFSET …` (пагінація)

### Контекст

Сторінка 3 пошуку по клієнтах (10 на сторінку — отже рядки 21-30).

### Чого ви навчитеся

- `LIMIT n OFFSET m` для stateless-пагінації.
- Чому `ORDER BY` стає обов'язковим при пагінації.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `customers` | `id`, `first_name`, `last_name` |

### Завдання

Повернути рядки 21-30 з `customers` (`id BETWEEN 1 AND 500`), відсортувавши за `id` зростанням.

### Очікуваний результат (реальні рядки з дампу)

```text
+----+------------+------------+
| id | first_name | last_name  |
+----+------------+------------+
| 21 | Name_21    | Surname_21 |
| 22 | Name_22    | Surname_22 |
| ...|            |            |
| 30 | Name_30    | Surname_30 |
+----+------------+------------+
```

### Підказка

`OFFSET 20` пропускає перші 20 рядків; `LIMIT 10` бере наступні 10.

### Розв'язання

```sql
SELECT id,
       first_name,
       last_name
FROM customers
WHERE id BETWEEN 1 AND 500
ORDER BY id
LIMIT 10 OFFSET 20;
```

### Покрокове пояснення

1. **`OFFSET m`** відраховує рядки з початку відсортованого результату; **перший рядок — це offset 0**.
2. **`ORDER BY` обов'язковий** для пагінації. Без нього можна побачити дублікати або пропустити рядки між сторінками.
3. **Продуктивність:** `OFFSET 1000000` повільний — MySQL має відкинути мільйон рядків. Для дуже глибоких сторінок використовуйте keyset-пагінацію (`WHERE id > last_seen_id`).

## Вправа S1 — `INNER JOIN` (vehicles + назва бренду)

### Контекст

Форма прийому авто на СТО показує назву бренду поруч із номером — але `vehicles` зберігає тільки `brand_id`. Потрібен `JOIN` з `car_brands` для людяної назви.

### Чого ви навчитеся

- Найпростішому `INNER JOIN` по зовнішньому ключу.
- Аліасам таблиць для читабельності.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `vehicles` | `id`, `plate`, `brand_id` |
| `car_brands` | `id`, `name` |

### Завдання

Повернути `vehicle_id`, `plate`, `brand_name` для `v.id BETWEEN 1 AND 150`. Limit 25.

### Очікуваний результат (реальні рядки з дампу)

```text
+------------+----------+------------+
| vehicle_id | plate    | brand_name |
+------------+----------+------------+
|          1 | AA0001BB | Brand_001  |
|          2 | AA0002BB | Brand_002  |
| ...        |          |            |
|         25 | AA0025BB | Brand_025  |
+------------+----------+------------+
```

### Підказка

`INNER JOIN car_brands b ON b.id = v.brand_id`.

### Розв'язання

```sql
SELECT v.id    AS vehicle_id,
       v.plate,
       b.name  AS brand_name
FROM vehicles  AS v
INNER JOIN car_brands AS b ON b.id = v.brand_id
WHERE v.id BETWEEN 1 AND 150
LIMIT 25;
```

### Покрокове пояснення

1. **`INNER JOIN`** повертає лише рядки, у яких є збіг у **обох** таблицях. Якби `vehicles.brand_id` був `NULL`, рядок випав би — для збереження лівої сторони використовуйте `LEFT JOIN`.
2. **`ON b.id = v.brand_id`** — умова з'єднання. Через `USING (brand_id)` можна вкоротити, якщо обидві колонки називаються однаково.
3. **Аліаси `v` / `b`** роблять запит читабельним. Без них кожен стовпець потребував би повного імені таблиці.

## Вправа S2 — Мульти-таблиця `JOIN` (work order + vehicle + customer)

### Контекст

Шапка чека: id замовлення, прізвище клієнта, номер авто, сума — це мінімум, який касир друкує.

### Чого ви навчитеся

- Ланцюжку з двох `INNER JOIN`.
- Чому порядок з'єднаних таблиць для `INNER JOIN` не змінює семантики.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `work_orders` | `id`, `vehicle_id`, `total_cost` |
| `vehicles` | `id`, `customer_id`, `plate` |
| `customers` | `id`, `last_name` |

### Завдання

Повернути `work_order_id`, `customers.last_name`, `vehicles.plate`, `work_orders.total_cost` для `wo.id BETWEEN 1 AND 200`. Limit 20.

### Очікуваний результат (реальні рядки з дампу)

```text
+---------------+-----------+----------+------------+
| work_order_id | last_name | plate    | total_cost |
+---------------+-----------+----------+------------+
|             1 | Surname_1 | AA0001BB |     500.10 |
|             2 | Surname_2 | AA0002BB |     500.20 |
| ...           |           |          |            |
|            20 | Surname_20| AA0020BB |     502.00 |
+---------------+-----------+----------+------------+
```

### Підказка

Ланцюжок: `work_orders → vehicles (за vehicle_id) → customers (за customer_id)`.

### Розв'язання

```sql
SELECT wo.id      AS work_order_id,
       c.last_name,
       v.plate,
       wo.total_cost
FROM work_orders AS wo
INNER JOIN vehicles  AS v ON v.id = wo.vehicle_id
INNER JOIN customers AS c ON c.id = v.customer_id
WHERE wo.id BETWEEN 1 AND 200
LIMIT 20;
```

### Покрокове пояснення

1. **З'єднуйте таблиці за зовнішніми ключами.** Ланцюжок `work_orders → vehicles → customers` повторює реальну ієрархію.
2. **Кожен `ON` поєднує наступну пару.** Забути один — створити декартів добуток (всі рядки `work_orders` × всі рядки `vehicles`), і це можуть бути мільйони рядків.
3. **`INNER JOIN` відкидає рядки без збігу.** Якщо у деяких авто `customer_id IS NULL`, такі замовлення не з'являться — у таких випадках використовуйте `LEFT JOIN`.

## Діагностика: мій запит повернув 0 рядків

| Симптом | Імовірне виправлення |
|---|---|
| Порожнє з фільтром `WHERE id BETWEEN x AND y` | Розширте діапазон; у таблицях ~100 тис. рядків. |
| Порожнє після `HAVING` | Знизьте пороги `COUNT` / `AVG`. |
| `LIKE 'pattern%'` нічого не знаходить | Перевірте регістр; пам'ятайте: `_` — теж wildcard. |
| `IS NOT NULL` нічого не повертає | Перевірте, чи у колонці взагалі є не-`NULL`: `SELECT COUNT(*) FROM t WHERE col IS NULL`. |
| Пагінація пропускає або дублює рядки | Додайте стабільне `ORDER BY` (останнім ключем — `id`). |

Щоб запустити **усі** приклади одним проходом: `mysql -t -u root car_service_db < 03_mysql/04_dql/car_service_dql_examples.sql`.
