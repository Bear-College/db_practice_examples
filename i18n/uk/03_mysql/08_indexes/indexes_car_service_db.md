# Індекси — лабораторія `car_service_db`

> Translation / Переклад: [English](../../../../03_mysql/08_indexes/indexes_car_service_db.md)

Цей модуль додає **навчальну таблицю** `idx_lab` (і крихітну `idx_geo` для **просторових** індексів) всередину **`car_service_db`**. Ви можете самостійно виконувати **`CREATE INDEX`** / **`DROP INDEX`** і порівнювати плани й часи **з** та **без** індексу.

**Скрипт:** `08_indexes/car_service_indexes_examples.sql`

```bash
gunzip -c 01_database_mysql/car_service_db.sql.gz | mysql -u ... -p ... car_service_db
mysql -u ... -p ... car_service_db < 08_indexes/car_service_indexes_examples.sql
```

**Вимоги:** рекомендовано MySQL **8.0+** (функціональні індекси, `EXPLAIN ANALYZE`, індекси за виразом). Деякі інструкції захищено приміткою про версію всередині `.sql`-файлу.

---

## Як вручну порівнювати швидкість

1. Запустіть **базові** блоки `EXPLAIN` / `EXPLAIN ANALYZE` **до** створення вторинного індексу (порядок у скрипті це передбачає).
2. Виконайте відповідний **`CREATE INDEX`** (або розкоментуйте його, якщо перенесли під базовий заміри).
3. Повторно виконайте **той самий `SELECT`** і порівняйте:
   - **`EXPLAIN`**: `type` має зміститися з **`ALL`** (повний скан) до **`ref`**, **`range`** або **`const`**, коли індекс застосовується.
   - **`EXPLAIN ANALYZE`** (8.0.18+): порівняйте **фактичний час** / **прочитані рядки**.
4. Зніміть індекс, щоб знову протестувати «холодний» скан:
   ```sql
   DROP INDEX index_name ON idx_lab;
   ```
5. Опційно: `ANALYZE TABLE idx_lab;` після масового завантаження або великої кількості DML.

**Примітка:** `SHOW PROFILES` / `profiling` застаріли у нових версіях MySQL; за можливості віддавайте перевагу **`EXPLAIN ANALYZE`**.

## Типи індексів, що демонструються (MySQL / InnoDB)

| Тип | У скрипті | Типове використання |
|-----|-----------|---------------------|
| **Первинний ключ** | `PRIMARY KEY (id)` у лаб-таблицях | Кластерний B-tree; унікальний id рядка. |
| **Вторинний B-tree (неунікальний)** | `CREATE INDEX … ON idx_lab (ref_num)` | Рівність / діапазон на `ref_num`. |
| **UNIQUE** | `CREATE UNIQUE INDEX … ON idx_lab (sku)` | Один рядок на SKU (дані мають лишатися унікальними). |
| **Складений** | `(status, ref_num)` | Фільтри за провідним стовпцем + сортування/діапазон за наступним. |
| **Префіксний** | `sku(16)` на довгому `VARCHAR` | Коротший індекс за початком рядка. |
| **FULLTEXT** | `FULLTEXT (note)` | `MATCH(note) AGAINST(...)` (InnoDB FULLTEXT). |
| **Функціональний / за виразом** (8.0.13+) | `(LOWER(sku))` | Рівність на виразі, що використовується в `WHERE`. |
| **SPATIAL** | `POINT` + `SPATIAL INDEX` на `idx_geo` | Запити на кшталт «точка в регіоні» (мала демо-таблиця). |

**Не включено (рідко у прикладних БД):** `HASH` доступний лише для рушія **`MEMORY`**, не для вторинних індексів InnoDB за замовчуванням.

**Опціонально (MySQL 8+):** **descending** вторинний індекс (`CREATE INDEX … (col DESC)`), **invisible**-індекси (`CREATE INDEX … INVISIBLE`) для A/B-тестування — див. посібник MySQL; для цієї лабораторії не обов'язкові.

## Прибирання

Скрипт завершується опціональним **`DROP TABLE`** для лаб-таблиць. Закоментуйте ці рядки, якщо хочете продовжити експерименти. Імена індексів починаються з префіксу **`ix_`**, щоб ви могли знайти їх у `SHOW INDEX FROM idx_lab`.

---

## Усунення проблем

- **`CREATE UNIQUE INDEX` падає:** в `idx_lab` є дублікати `sku` — очистіть таблицю та повторіть або послабте до неунікального індексу на `sku`.
- **FULLTEXT нічого не повертає:** стоп-слова / довжина токена — спробуйте довше слово з ваших даних у `MATCH … AGAINST`.
- **Помилки `SPATIAL`:** потрібен MySQL 8+ з підтримкою просторових даних InnoDB; переконайтеся, що `POINT` має `NOT NULL` і SRID збігається.
