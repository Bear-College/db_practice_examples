# Збережені процедури — `car_service_db`

> Translation / Переклад: [English](../../../../03_mysql/14_procedures/procedures_car_service_db.md)

Ці вправи проходять **збережені процедури MySQL** — іменовані серверні блоки SQL з параметрами **`IN`**, **`OUT`**, **`INOUT`**, локальними змінними через **`DECLARE`**, умовним **`IF`** та викликом через **`CALL`**. Виконуються на справжній базі з **`01_database_mysql/car_service_db.sql.gz`** (ім'я бази: **`car_service_db`**).

Готові запити лежать у файлі-компаньйоні: [`14_procedures/car_service_procedures_examples.sql`](../../../../03_mysql/14_procedures/car_service_procedures_examples.sql).

```bash
mysql -u root -e "CREATE DATABASE IF NOT EXISTS car_service_db;"
gunzip -c 01_database_mysql/car_service_db.sql.gz | mysql -u root car_service_db
mysql -u root car_service_db < 03_mysql/14_procedures/car_service_procedures_examples.sql
```

Завжди використовуйте клієнт **`mysql`** (а не GUI), коли завантажуєте файл з процедурами: лише цей клієнт коректно обробляє **`DELIMITER $$`**, який потрібен, щоб MySQL відрізняв внутрішні `;` (закінчення інструкцій усередині `BEGIN … END`) від зовнішнього кінця оператора.

## Карта конструкцій процедур (відповідає матеріалам курсу)

| Тема | Ідеї SQL |
|--------|-----------|
| **`CREATE PROCEDURE name(...)`** | Визначити іменований багаторазовий блок SQL, що зберігається на сервері. |
| **`DELIMITER $$`** | Тимчасово змінити роздільник інструкцій, щоб `;` міг з'являтись усередині тіла. |
| **Параметр `IN`** | Тільки для читання (значення за замовчуванням, якщо напрямок не вказано). |
| **Параметр `OUT`** | Тільки для запису; викликач читає з `@user_var`. |
| **Параметр `INOUT`** | Читати **й** записувати ту саму `@user_var`. |
| **`DECLARE var TYPE DEFAULT …`** | Локальна змінна в межах `BEGIN … END`. |
| **`SET var := expr`** | Присвоєння локальній змінній або `@user_var`. |
| **`SELECT … INTO var`** | Зчитати одно-рядкове скалярне значення у змінну. |
| **`IF … THEN … ELSE … END IF`** | Розгалуження за умовою в тілі. |
| **`CALL proc(...)`** | Виконати процедуру; для `OUT` / `INOUT` передавати `@vars`. |
| **`DROP PROCEDURE IF EXISTS name`** | Ідемпотентне перестворення під час розробки. |

**Безпека:** у продакшні віддавайте перевагу **`DEFINER`** / **`SQL SECURITY INVOKER`** та мінімальним привілеям. Ці лаб-приклади використовують значення за замовчуванням з освітньою метою.

## Вправа 1 — параметри `IN`, що повертають набір результатів

### Контекст

Диспетчеру потрібен параметризований звіт «покажи перші *N* замовлень у статусі *X*» — той самий запит, але з різними фільтрами щогодини. Загорнувши його у збережену процедуру, кожна UI-кнопка чи cron-задача зможе викликати одне визначення.

### Чого ви навчитеся

- Оголошувати процедуру з двома параметрами **`IN`**.
- Повертати **набір результатів**, завершуючи тіло звичайним `SELECT`.
- Використовувати **`DELIMITER $$`**, щоб `;` усередині `BEGIN … END` не завершував `CREATE PROCEDURE`.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `work_orders` | `id`, `vehicle_id`, `assigned_mechanic_id`, `status`, `total_cost` |

### Завдання

1. Визначити `sp_work_orders_by_status(IN p_status VARCHAR(20), IN p_limit INT)`.
2. Тіло повертає `id, vehicle_id, assigned_mechanic_id, status, total_cost` для рядків, де `status = p_status` і `id BETWEEN 1 AND 100000`, відсортованих за `id`, з лімітом `p_limit`.
3. Викликати з `('completed', 8)` і переконатися, що повернеться вісім рядків.

### Очікуваний результат (реальні рядки з `CALL sp_work_orders_by_status('completed', 8)`)

```text
+----+------------+----------------------+-----------+------------+
| id | vehicle_id | assigned_mechanic_id | status    | total_cost |
+----+------------+----------------------+-----------+------------+
|  4 |          4 |                    4 | completed |     500.40 |
|  9 |          9 |                    9 | completed |     500.90 |
| 14 |         14 |                   14 | completed |     501.40 |
| 19 |         19 |                   19 | completed |     501.90 |
| 24 |         24 |                   24 | completed |     502.40 |
| 29 |         29 |                   29 | completed |     502.90 |
| 34 |         34 |                   34 | completed |     503.40 |
| 39 |         39 |                   39 | completed |     503.90 |
+----+------------+----------------------+-----------+------------+
```

### Підказка

Загорніть звичайний `SELECT … WHERE status = p_status … LIMIT p_limit` у `BEGIN … END` і спочатку змініть роздільник на `$$`.

### Розв'язання

```sql
DROP PROCEDURE IF EXISTS sp_work_orders_by_status;

DELIMITER $$

CREATE PROCEDURE sp_work_orders_by_status(
  IN p_status VARCHAR(20),
  IN p_limit  INT
)
BEGIN
  SELECT id,
         vehicle_id,
         assigned_mechanic_id,
         status,
         total_cost
  FROM work_orders
  WHERE status = p_status
    AND id BETWEEN 1 AND 100000
  ORDER BY id
  LIMIT p_limit;
END$$

DELIMITER ;

CALL sp_work_orders_by_status('completed', 8);
```

### Покрокове пояснення

1. **`DROP PROCEDURE IF EXISTS`** робить скрипт перезапускним: без нього другий запуск помиляється з *"PROCEDURE already exists"*.
2. **`DELIMITER $$`** каже клієнту `mysql` сприймати `$$` (а не `;`) як кінець інструкції — тож внутрішні `;` усередині `BEGIN … END` належать тілу процедури.
3. **`IN p_status VARCHAR(20)`** — напрямок параметра за замовчуванням. Викликач передає рядок; тіло може лише його прочитати. Запис у параметр `IN` не повертається назад до викликача.
4. **`BEGIN … END`** — складена інструкція, що стає тілом процедури. Між ними може бути будь-яка кількість SQL- чи керівних інструкцій.
5. **Завершальний `SELECT`** без `INTO` повертає **набір результатів** тому, хто викликав процедуру — так само як звичайний топ-рівневий запит.
6. **`DELIMITER ;`** відновлює стандартний роздільник, щоб подальші інструкції парсилися нормально.
7. **`CALL sp_work_orders_by_status('completed', 8)`** виконує процедуру і друкує набір. Аргументи зв'язуються позиційно; іменованих аргументів у процедурах MySQL не існує.

## Вправа 2 — параметр `OUT` (агрегат у користувацьку змінну)

### Контекст

Моніторинговий дашборд опитує сервер щохвилини на предмет «загальної виручки перших 50 000 замовлень», щоб годувати панель Grafana. Загорнувши агрегат у процедуру з параметром **`OUT`**, поллер може викликати одну добре названу точку входу замість того, щоб всюди копіювати той самий `SUM`.

### Чого ви навчитеся

- Оголошувати параметр **`OUT`** і записувати в нього.
- **`SELECT … INTO p_var`**, щоб згорнути скалярний агрегат у параметр.
- Використовувати **`COALESCE(SUM(...), 0)`**, щоб не повертати `NULL` для порожнього діапазону.
- Читати результат через сесійну **`@user_variable`**.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `work_orders` | `id`, `total_cost` |

### Завдання

1. Визначити `sp_sum_cost_slice(OUT p_sum DECIMAL(14,2))`.
2. Тіло: присвоїти `COALESCE(SUM(total_cost), 0)` по `work_orders` з `id BETWEEN 1 AND 50000` у `p_sum`.
3. Викликати як `CALL sp_sum_cost_slice(@cost_sum)` і прочитати `@cost_sum`.

### Очікуваний результат (реальні рядки)

```text
+----------------------+
| sum_total_cost_slice |
+----------------------+
|         149997500.00 |
+----------------------+
```

### Підказка

`SELECT COALESCE(SUM(col), 0) INTO p_sum FROM …` — рівно один скалярний рядок, рівно одна цільова змінна.

### Розв'язання

```sql
DROP PROCEDURE IF EXISTS sp_sum_cost_slice;

DELIMITER $$

CREATE PROCEDURE sp_sum_cost_slice(
  OUT p_sum DECIMAL(14,2)
)
BEGIN
  SELECT COALESCE(SUM(total_cost), 0)
  INTO p_sum
  FROM work_orders
  WHERE id BETWEEN 1 AND 50000;
END$$

DELIMITER ;

CALL sp_sum_cost_slice(@cost_sum);
SELECT @cost_sum AS sum_total_cost_slice;
```

### Покрокове пояснення

1. **`OUT p_sum DECIMAL(14,2)`** — викликач має передати сюди **сесійну користувацьку змінну** (`@cost_sum`), а не літерал. Після `CALL` ця змінна зберігає те, що записало тіло.
2. **`SELECT … INTO p_sum`** — процедурна форма присвоєння: запит має повернути рівно один рядок і одну колонку, інакше MySQL виведе помилку.
3. **`COALESCE(SUM(total_cost), 0)`** захищає від випадку «порожній діапазон». `SUM` над нулем рядків повертає `NULL`, який мовчки заплутав би дашборд.
4. **`CALL sp_sum_cost_slice(@cost_sum)`** — на місці виклику `@cost_sum` автоматично створюється в сесії, якщо її ще не було. Семантика `OUT` означає, що попереднє значення тіло **ігнорує**.
5. **`SELECT @cost_sum`** читає змінну назад. `@vars` живуть протягом усього з'єднання, тож наступний `CALL` у тій самій сесії може продовжити її використовувати.

## Вправа 3 — `IN` + `OUT` + `DECLARE` + `IF`

### Контекст

Задача сегментації клієнтів запитує «скільки клієнтів потрапляє у заданий діапазон id?» Вона має бути захищеною: якщо викликач передає некоректний діапазон (max < min), процедура має повернути `0`, а не запускати дорогий запит.

### Чого ви навчитеся

- Поєднувати параметри **`IN`** і **`OUT`**.
- **`DECLARE v_var INT DEFAULT …`** для локальної змінної в тілі.
- **`IF condition THEN … ELSE … END IF`** для захищених гілок.
- Чому локальні змінні (`v_span`) і параметри (`p_min_id`) живуть у різних просторах імен.

### Задіяні таблиці

| Таблиця | Колонки |
|---|---|
| `customers` | `id` |

### Завдання

1. Визначити `sp_customer_count(IN p_min_id INT, IN p_max_id INT, OUT p_cnt INT)`.
2. Оголосити локальну `v_span` = `p_max_id - p_min_id`.
3. Якщо `v_span < 0`, присвоїти `p_cnt := 0` і зупинитись. Інакше `SELECT COUNT(*) INTO p_cnt FROM customers WHERE id BETWEEN p_min_id AND p_max_id`.
4. Викликати двічі: з валідним діапазоном `(1, 500)` і з перевернутим `(900, 100)`.

### Очікуваний результат (реальні рядки)

```text
+--------------------+
| customers_in_range |
+--------------------+
|                500 |
+--------------------+
+------------------+
| bad_range_result |
+------------------+
|                0 |
+------------------+
```

### Підказка

`DECLARE v_span INT DEFAULT 0;` має йти **до** будь-якого `SET` або `SELECT` у тілі — усі оголошення стоять першими в межах блоку `BEGIN … END`.

### Розв'язання

```sql
DROP PROCEDURE IF EXISTS sp_customer_count;

DELIMITER $$

CREATE PROCEDURE sp_customer_count(
  IN  p_min_id INT,
  IN  p_max_id INT,
  OUT p_cnt    INT
)
BEGIN
  DECLARE v_span INT DEFAULT 0;
  SET v_span := p_max_id - p_min_id;
  IF v_span < 0 THEN
    SET p_cnt := 0;
  ELSE
    SELECT COUNT(*)
    INTO p_cnt
    FROM customers
    WHERE id BETWEEN p_min_id AND p_max_id;
  END IF;
END$$

DELIMITER ;

CALL sp_customer_count(1, 500, @cust_n);
SELECT @cust_n AS customers_in_range;

CALL sp_customer_count(900, 100, @bad);
SELECT @bad AS bad_range_result;
```

### Покрокове пояснення

1. **`DECLARE v_span INT DEFAULT 0`** уводить локальну змінну. Оголошення мають передувати будь-якій виконуваній інструкції у блоці — поставити їх після `SET` буде синтаксичною помилкою в MySQL.
2. **`SET v_span := p_max_id - p_min_id`** використовує **`:=`** (присвоєння) — у цій позиції еквівалентне `=`, але `:=` однозначне і працює так само й усередині `SELECT`.
3. **`IF v_span < 0 THEN … ELSE … END IF`** — єдина конструкція розгалуження. Існує також `ELSEIF` для ланцюгових перевірок; **не плутайте** з функцією `IF()` (це вираз).
4. **Захищена гілка** присвоює `p_cnt := 0` — важливо, бо альтернатива `SELECT … INTO p_cnt` інакше або поверне `NULL` (нуль рядків), або, з перевернутим діапазоном, проскане більше рядків, ніж очікувалось.
5. **Два виклики** доводять обидві гілки: `(1, 500)` потрапляє в `ELSE` і повертає 500; `(900, 100)` потрапляє в захист `IF` і повертає 0 без сканування таблиці.

## Вправа 4 — параметр `INOUT` (мутація сесійної змінної)

### Контекст

Допоміжна процедура логування дозволяє викликачу передати наявний текстовий тег і **дописати** до нього статус-токен (` | proc_ok`), перш ніж передати далі. Та сама змінна читається і записується — саме для цього і потрібен `INOUT`.

### Чого ви навчитеся

- Оголошувати параметр **`INOUT`**.
- Зчитати поточне значення `INOUT` і перезаписати його новим.
- Використовувати **`IFNULL(col, default)`**, щоб зробити конкатенацію рядків `NULL`-безпечною.
- Зберігати стан між кількома `CALL` у тій самій сесії.

### Задіяні таблиці

Жодної таблиці — лише робота з параметрами.

### Завдання

1. Визначити `sp_append_tag(INOUT p_text VARCHAR(200))`.
2. У тілі присвоїти `p_text := CONCAT(IFNULL(p_text, ''), ' | proc_ok')`.
3. Виконати `SET @tag := 'lab'`, далі `CALL sp_append_tag(@tag)`, потім викликати ще раз, щоб побачити, що тег нарощується.

### Очікуваний результат (реальні рядки)

```text
+-----------------+
| tag_after_inout |
+-----------------+
| lab | proc_ok   |
+-----------------+
+-------------------------+
| tag_after_second_inout  |
+-------------------------+
| lab | proc_ok | proc_ok |
+-------------------------+
```

### Підказка

`CONCAT(IFNULL(p_text, ''), ' | proc_ok')` — `IFNULL` міняє `NULL` на порожній рядок, тож перший символ результату завжди визначений.

### Розв'язання

```sql
DROP PROCEDURE IF EXISTS sp_append_tag;

DELIMITER $$

CREATE PROCEDURE sp_append_tag(
  INOUT p_text VARCHAR(200)
)
BEGIN
  SET p_text := CONCAT(IFNULL(p_text, ''), ' | proc_ok');
END$$

DELIMITER ;

SET @tag := 'lab';
CALL sp_append_tag(@tag);
SELECT @tag AS tag_after_inout;

CALL sp_append_tag(@tag);
SELECT @tag AS tag_after_second_inout;
```

### Покрокове пояснення

1. **`INOUT`** — це «передача за посиланням»: викликач мусить надати `@user_variable` (літерали відхиляються), тіло бачить її поточне значення **та** може його перезаписати.
2. **`CONCAT(IFNULL(p_text, ''), ' | proc_ok')`** — без `IFNULL` вхідний `NULL` проштовхнеться крізь `CONCAT`, і весь результат стане `NULL`. Завжди нормалізуйте nullable-рядки перед конкатенацією.
3. **`SET @tag := 'lab'`** ініціалізує сесійну змінну. Після першого `CALL` змінна стає `'lab | proc_ok'`; другий `CALL` читає це нове значення і додає ще раз — отримуючи `'lab | proc_ok | proc_ok'`. Саме це й означає «in **and** out».
4. **Типова помилка:** передача літералу — `CALL sp_append_tag('lab')` падає з *"OUT or INOUT argument is not a variable"*. Збережені процедури не вміють писати назад у незмінний літерал.

## Усунення проблем: процедура не завантажується

| Симптом | Імовірне виправлення |
|---|---|
| Синтаксична помилка на першому `;` усередині `BEGIN … END` | Ви забули **`DELIMITER $$`** перед `CREATE PROCEDURE`. |
| `PROCEDURE … already exists` при повторному запуску | Додайте **`DROP PROCEDURE IF EXISTS name;`** перед `CREATE`. |
| `OUT or INOUT argument is not a variable` | Передавайте `@user_var` (напр., `@sum`), а не літерал. |
| `@var` дорівнює `NULL` після `CALL` | Процедура впала з помилкою до запису — перевірте `SHOW WARNINGS;`. |
| `Variable 'foo' must be declared` усередині `BEGIN…END` | Оголошення мають іти **до** будь-якої виконуваної інструкції в блоці. |
| Завантаження через GUI-інструмент падає на `DELIMITER` | Деякі GUI ігнорують `DELIMITER` — вантажте через CLI `mysql`. |

Щоб запустити **всі** приклади одразу: `mysql -t -u root car_service_db < 03_mysql/14_procedures/car_service_procedures_examples.sql`.
