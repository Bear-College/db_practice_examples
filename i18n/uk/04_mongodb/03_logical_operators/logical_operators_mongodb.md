# Логічні оператори у MongoDB (`03_logical_operators`)

> Translation / Переклад: [English](../../../../04_mongodb/03_logical_operators/logical_operators_mongodb.md)

Ці вправи охоплюють **чотири логічні оператори** мови запитів MongoDB: `$and`, `$or`, `$not`, `$nor`. Вони комбінують простіші предикати (`$gte`, `$lt`, …) у складні фільтри.

Усі приклади виконуються на базі `edu_academy_seed` і колекції **`logical_operators_people`**.

Готовий приклад: [`03_logical_operators/example.py`](../../../../04_mongodb/03_logical_operators/example.py). Скрипт демонструє `$and`, `$or`, `$not`; вправа з `$nor` нижче знята окремо через `mongosh` на тій же seed-колекції.

```bash
pip install -r 04_mongodb/requirements.txt
python 04_mongodb/03_logical_operators/example.py
```

Налаштування за замовчуванням:

- `MONGODB_URI=mongodb://localhost:27017`
- `MONGODB_DB=edu_academy_seed`

## Карта: логічні оператори

| Оператор | Значення | Форма |
|---|---|---|
| `$and` | Усі предикати істинні | `{ "$and": [ {…}, {…} ] }` |
| `$or` | Принаймні один предикат істинний | `{ "$or": [ {…}, {…} ] }` |
| `$not` | Предикат хибний (або поле відсутнє) | `{ field: { "$not": { … } } }` |
| `$nor` | Жоден предикат не істинний | `{ "$nor": [ {…}, {…} ] }` |

Важлива деталь: запит на кшталт `{"age": {"$gte": 18}, "city": "New York"}` — це **неявний `$and`**. Явний `$and` потрібен, тільки коли два предикати торкаються **одного й того ж поля**, або заради читабельності.

## Схема колекції

```json
{ "name": "Anna", "age": 17, "city": "Chicago" }
```

| Поле | Тип BSON | Приклади |
|---|---|---|
| `name` | `string` | Anna, Bohdan, Chris, Daria, Emma, Farid, Hanna |
| `age` | `int` | 17, 18, 25, 30, 45, 60, 61 |
| `city` | `string` | Chicago, New York, Los Angeles, Kyiv, Berlin, Warsaw |

Seed вставляє 7 документів.

---

## Вправа 1 — `$and` (логічне AND)

### Контекст

Офіс у New York проводить вечір «18+». HR-система має знайти всіх співробітників, які **живуть у New York** **І** **мають ≥ 18 років**.

### Чого ви навчитеся

- Явній формі `$and` для комбінації предикатів.
- Коли вистачає неявного AND, а коли `$and` обов'язковий.

### Колекція

| Поле | Предикат |
|---|---|
| `age` | `>= 18` |
| `city` | `== "New York"` |

### Завдання

Знайти людей з `age >= 18` **і** `city == "New York"`, відсортовано за `name`.

### Очікуваний результат

```text
$and (logical AND)
  query={'$and': [{'age': {'$gte': 18}}, {'city': 'New York'}]}
  count=2
  docs=[Bohdan (age=18, city=New York), Emma (age=45, city=New York)]
```

### Підказка

`$and` приймає **список піддокументів**: `{"$and": [ {...}, {...} ]}`.

### Розв'язання

```python
docs = list(coll.find(
    {"$and": [{"age": {"$gte": 18}}, {"city": "New York"}]},
    {"_id": 0},
).sort("name", 1))
```

```javascript
db.logical_operators_people.find(
  { $and: [ { age: { $gte: 18 } }, { city: "New York" } ] },
  { _id: 0 }
).sort({ name: 1 })
```

### Покрокове пояснення

1. **Неявний AND** теж спрацює: `{"age": {"$gte": 18}, "city": "New York"}` еквівалентний. Ми обрали `$and` заради **читабельності** і структури, знайомої тим, хто звик до SQL `WHERE … AND …`.
2. **Коли явний `$and` *обов'язковий*:** два предикати на **одному й тому ж полі**, наприклад `{"$and": [{"age": {"$gte": 18}}, {"age": {"$lt": 65}}]}` — у звичайному dict-літералі другий ключ `age` тихо переписав би перший.
3. **Short-circuit:** MongoDB перебирає предикати зліва направо і зупиняється на першому, що не пройшов. Ставте **найвибірковіший** предикат першим, щоб відсіювати більше.
4. **Документи без потрібних полів не збігаються** — і `$gte`, і `$eq` вимагають присутності поля.

## Вправа 2 — `$or` (логічне OR)

### Контекст

Кампанія здоров'я націлена на два крайні вікові сегменти: **неповнолітні (< 18)** і **пенсіонери (> 60)**. Надіслати флаєр кожному, хто в одній із груп.

### Чого ви навчитеся

- Оператору `$or` з кількома піддокументами.
- Чому `$or` стає **об'єднанням index scans**, якщо кожна гілка проіндексована.

### Колекція

| Поле | Предикати |
|---|---|
| `age` | `< 18` OR `> 60` |

### Завдання

Знайти людей з `age < 18` **або** `age > 60`, відсортовано за `name`.

### Очікуваний результат

```text
$or (logical OR)
  query={'$or': [{'age': {'$lt': 18}}, {'age': {'$gt': 60}}]}
  count=2
  docs=[Anna (age=17, city=Chicago), Hanna (age=61, city=Warsaw)]
```

### Підказка

`{"$or": [ {...}, {...} ]}` — список піддокументів, кожен оцінюється незалежно.

### Розв'язання

```python
docs = list(coll.find(
    {"$or": [{"age": {"$lt": 18}}, {"age": {"$gt": 60}}]},
    {"_id": 0},
).sort("name", 1))
```

```javascript
db.logical_operators_people.find(
  { $or: [ { age: { $lt: 18 } }, { age: { $gt: 60 } } ] },
  { _id: 0 }
).sort({ name: 1 })
```

### Покрокове пояснення

1. **`$or` потребує явного оператора** — на відміну від AND, неявної форми не існує. Один dict не може представити OR.
2. **Індекси:** Mongo планує **об'єднання index scans**, якщо у кожної гілки є придатний індекс. З єдиним `{age: 1}` обидві гілки стають диз'юнктними range scans по тому самому індексу — швидко.
3. **Дублікати усуваються автоматично**, коли один документ задовольняє кілька гілок; «двічі підрахувати» неможливо.
4. **Порожній `$or`** — `{"$or": []}` — кидає помилку. Мінімум — один піддокумент.

## Вправа 3 — `$not` (логічне NOT)

### Контекст

Правило шкільної програми: видрукувати бейджи всім, чий `age` **не** у «дорослому» діапазоні (`>= 18`). У наших даних єдина неповнолітня — Anna (17).

### Чого ви навчитеся

- Оператору `$not` на рівні поля (інвертує один предикат).
- Як `$not` поводиться з відсутніми полями.

### Колекція

| Поле | Предикат |
|---|---|
| `age` | НЕ (`>= 18`) |

### Завдання

Знайти людей, у яких вік **не** ≥ 18, відсортовано за `name`.

### Очікуваний результат

```text
$not (logical NOT)
  query={'age': {'$not': {'$gte': 18}}}
  count=1
  docs=[Anna (age=17, city=Chicago)]
```

### Підказка

`{"age": {"$not": {"$gte": 18}}}` — `$not` обгортає **інший операторний вираз**, не «голе» значення.

### Розв'язання

```python
docs = list(coll.find(
    {"age": {"$not": {"$gte": 18}}},
    {"_id": 0},
).sort("name", 1))
```

```javascript
db.logical_operators_people.find(
  { age: { $not: { $gte: 18 } } },
  { _id: 0 }
).sort({ name: 1 })
```

### Покрокове пояснення

1. **`$not` працює на рівні поля**, а не на верхньому рівні запиту. Форма: `{ field: { "$not": { <operator-expression> } } }`. Аргумент **має бути dict-оператором** на кшталт `{"$gte": 18}` — у деяких старих драйверах він не приймає «голе» значення чи regex-літерал.
2. **`$not` включає документи з відсутнім полем** — та сама пастка, що й у `$ne`. Якщо треба виключити, скомбінуйте з `{"age": {"$exists": true}}`.
3. **`$not` — це **не** `$nor`.** `$not` інвертує **один** предикат на **одному** полі; `$nor` інвертує **список** незалежних предикатів (див. Вправу 4).
4. **Індекси:** як і `$ne`/`$nin`, `$not` зазвичай не вміє ефективно скористатися індексом для одно-полевого пошуку, але може «їхати» компаундним індексом разом з іншими селективними предикатами.

## Вправа 4 — `$nor` (логічне NOR)

### Контекст

Маркетинг шукає сегмент «ні те, ні те»: люди, які **ні неповнолітні** (`age < 18`), **ні з New York**, — тобто ті, на кого кампанія для нью-йоркських підлітків **не** поширюється.

### Чого ви навчитеся

- Оператору `$nor`, який є `NOT (a OR b OR …)`.
- Чим `$nor` відрізняється від ланцюжка `$ne` / `$not`.

### Колекція

| Поле | Предикат, який виключаємо |
|---|---|
| `age` | `< 18` |
| `city` | `== "New York"` |

### Завдання

Знайти людей, у яких **жодне** з наступного не виконується: `age < 18`, `city == "New York"`. Сортувати за `name`.

### Очікуваний результат (знято з `mongosh` наживо)

```text
$nor count=4
[
  { name: 'Chris',  age: 25, city: 'Los Angeles' },
  { name: 'Daria',  age: 30, city: 'Kyiv' },
  { name: 'Farid',  age: 60, city: 'Berlin' },
  { name: 'Hanna',  age: 61, city: 'Warsaw' }
]
```

(Bohdan і Emma виключені, бо живуть у New York. Anna виключена, бо неповнолітня.)

### Підказка

`{"$nor": [ {...}, {...} ]}` — форма та сама, що в `$or`, але інвертована: документ лишається, тільки якщо **жоден** із підзапитів не пройшов.

### Розв'язання

```python
docs = list(coll.find(
    {"$nor": [{"age": {"$lt": 18}}, {"city": "New York"}]},
    {"_id": 0},
).sort("name", 1))
```

```javascript
db.logical_operators_people.find(
  { $nor: [ { age: { $lt: 18 } }, { city: "New York" } ] },
  { _id: 0 }
).sort({ name: 1 })
```

### Покрокове пояснення

1. **`$nor` — двійник `$or` за Де Морганом.** `NOT (A OR B)` дорівнює `(NOT A) AND (NOT B)`. Форма `$nor` компактніша і природніша для списків заперечень.
2. **Відсутні поля не виключаються.** Документ без `age` не задовольняє `age < 18`, тож `$nor` його лишає (за умови, що й інші предикати теж не пройшли). Це протилежно до поведінки `$or` на тих самих даних.
3. **Порівняно з `$not`:** `$not` інвертує один предикат на одному полі; `$nor` міксує предикати по різних полях. Беріть `$nor`, коли інакше довелося б писати ланцюжок `$ne` / `$not`, з'єднаних `$and`.
4. **Індекси:** як інші заперечення, `$nor` рідко індексо-дружній сам по собі. Використовуйте його як **вторинний фільтр** разом із хоча б одним позитивним селективним предикатом.

## Розв'язання типових проблем

| Симптом | Імовірне рішення |
|---|---|
| Неявний AND непомітно «з'їв» предикат | Два ключі на одному полі в одному dict — другий перетер перший. Перейдіть на явний `$and`. |
| `$or` повертає більше рядків, ніж очікувалося | Документи, що задовольняють кілька гілок, рахуються раз, але «поблажлива» гілка (наприклад, `$exists: true`) розширює множину. |
| `$not` повертає рядки, де поле відсутнє | Додайте `{ field: { "$exists": true } }`, щоб виключити їх. |
| `$nor` і «NOT IN» виглядають однаково | `$nor` загальніший — він інвертує будь-які предикати, не лише `$in`. |
| Повільний запит `$or` | Перевірте, що **кожна гілка** індексується незалежно; інакше планувальник скочується до collection scan. |
