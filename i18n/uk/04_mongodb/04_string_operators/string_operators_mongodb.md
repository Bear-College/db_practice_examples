# Рядкові оператори у MongoDB (`04_string_operators`)

> Translation / Переклад: [English](../../../../04_mongodb/04_string_operators/string_operators_mongodb.md)

Ці вправи охоплюють **три оператори пошуку у рядках** мови запитів MongoDB: `$regex`, його модифікатор `$options` та повнотекстовий `$text`.

Усі приклади виконуються на базі `edu_academy_seed` і колекції **`string_operators_people`**.

Готовий приклад: [`04_string_operators/example.py`](../../../../04_mongodb/04_string_operators/example.py). Він демонструє `$regex` (з якорем) і `$text` (повнотекст); вправа з `$regex + $options` нижче знята окремо через `mongosh` на тих самих seed-даних.

```bash
pip install -r 04_mongodb/requirements.txt
python 04_mongodb/04_string_operators/example.py
```

Налаштування за замовчуванням:

- `MONGODB_URI=mongodb://localhost:27017`
- `MONGODB_DB=edu_academy_seed`

Скрипт у кожному запуску заново створює колекцію і будує **текстовий індекс** по `bio` (`db.string_operators_people.createIndex({ bio: "text" }, { name: "ix_bio_text" })`), без якого `$text` не працюватиме.

## Карта: оператори рядкового пошуку

| Оператор | Призначення | Аналог у SQL |
|---|---|---|
| `$regex` | Зіставлення за шаблоном (PCRE) | `LIKE '…%'`, `REGEXP '…'` |
| `$options` | Модифікатори для `$regex`: `i` — без регістру, `m` — multiline, `s` — крапка ловить переноси, `x` — extended | (залежить від драйвера у SQL) |
| `$text` | Повнотекстовий пошук з індексом, стемінгом і скорингом | `MATCH(col) AGAINST('…')` |

## Схема колекції

```json
{ "name": "Anna", "email": "anna@gmail.com", "bio": "Frontend developer and UI engineer" }
```

| Поле | Тип BSON | Примітки |
|---|---|---|
| `name` | `string` | Ім'я людини. |
| `email` | `string` | Використовується для `$regex`. |
| `bio` | `string` | Використовується для `$regex+$options` і `$text`. Має **текстовий індекс**. |

Seed вставляє 4 документи (Anna, Bohdan, Chris, Daria).

## Вправа 1 — `$regex` (шаблон із якорем)

### Контекст

Маркетинг хоче список email для розсилки лише для Gmail. Потрібні всі користувачі, чий `email` **закінчується** на `@gmail.com`.

### Чого ви навчитеся

- Оператору `$regex` з рядком-шаблоном.
- Якорям (`$` — кінець рядка, `^` — початок рядка).
- Чому якорі важливі для продуктивності й коректності.

### Колекція

| Поле | Шаблон |
|---|---|
| `email` | `@gmail.com$` (закінчується на `@gmail.com`) |

### Завдання

Знайти всіх, чий `email` закінчується літерально на `@gmail.com`, відсортовано за `name`.

### Очікуваний результат

```text
$regex (similar to SQL LIKE)
  query={'email': {'$regex': '@gmail.com$'}}
  count=2
  docs=[Anna <anna@gmail.com>, Chris <chris@gmail.com>]
```

### Підказка

`{"email": {"$regex": "@gmail.com$"}}` — `$` у кінці — це regex-якір «кінець рядка», а **не** BSON-префікс.

### Розв'язання

```python
docs = list(coll.find(
    {"email": {"$regex": "@gmail.com$"}},
    {"_id": 0},
).sort("name", 1))
```

```javascript
db.string_operators_people.find(
  { email: { $regex: "@gmail.com$" } },
  { _id: 0 }
).sort({ name: 1 })
```

### Покрокове пояснення

1. **`$regex` — це PCRE** (Perl-сумісний). `^` — якір на початок, `$` — на кінець, `.` — будь-який символ, `\\.` (у JSON) — літеральна крапка.
2. **Крапка — мета-символ**: технічно `@gmail.com` зіставиться і з `@gmailXcom`. Для буквального збігу екрануйте: `"@gmail\\.com$"`. На 4 документах ми пощастили; у продакшені — завжди екранувати.
3. **З якорем vs без**: без `^` чи `$` regex шукає шаблон будь-де у полі. Не-якірний regex **не може ефективно скористатися btree-індексом** — MongoDB відкочується до collection scan. Лише regex виду `^foo` (лівий якір на проіндексованому рядковому полі) — швидкий випадок.
4. **PyMongo приймає й скомпільований `re.Pattern`** напряму: `{"email": re.compile("@gmail\\.com$")}` — еквівалентно і трохи безпечніше, бо Python сам екранує.

## Вправа 2 — `$regex` + `$options` (пошук без регістру)

### Контекст

Пошук у HR має знаходити людей, які згадують **"Python"** у своєму bio — але опечатки на кшталт `PYTHON` чи `python` теж мають збігатися. Потрібен пошук без врахування регістру.

### Чого ви навчитеся

- Модифікатору `$options` поруч із `$regex`.
- Прапору `i` (без регістру), `m` (multiline), `s` (крапка ловить переноси), `x` (extended/коментарі).
- Як комбінувати прапори.

### Колекція

| Поле | Шаблон | Прапори |
|---|---|---|
| `bio` | `PYTHON` | `i` (без регістру) |

### Завдання

Знайти всіх, у кого `bio` містить підрядок `python` (нечутливо до регістру), відсортовано за `name`.

### Очікуваний результат (знято з `mongosh` наживо)

```text
$regex+$options count=1
[
  {
    name: 'Bohdan',
    email: 'bohdan@outlook.com',
    bio: 'Backend developer working with Python'
  }
]
```

Лише в Bohdan в bio згадано Python.

### Підказка

Поставте `"$options": "i"` поряд із `"$regex": "..."` усередині того ж dict-оператора.

### Розв'язання

```python
docs = list(coll.find(
    {"bio": {"$regex": "PYTHON", "$options": "i"}},
    {"_id": 0},
).sort("name", 1))
```

```javascript
db.string_operators_people.find(
  { bio: { $regex: "PYTHON", $options: "i" } },
  { _id: 0 }
).sort({ name: 1 })
```

### Покрокове пояснення

1. **`$options` — рядок літер-прапорів.** Найчастіший — `i` (без регістру); `m` змушує `^`/`$` працювати порядково; `s` робить `.` таким, що ловить переноси; `x` дозволяє пробіли/коментарі у довгих regex. Комбінуйте літерами: `"im"`.
2. **`$options` має сенс лише поруч із `$regex`.** Окремо він не має ефекту.
3. **У PyMongo також є скорочення з compiled-regex**: `re.compile("python", re.IGNORECASE)`. PyMongo транслює прапори Python у `$options` під капотом — часто читабельніше.
4. **Пошук без регістру дорожчий**, бо Mongo не може використати звичайний індекс. На великих колекціях зберігайте окрему lowercase-копію поля і шукайте через `$eq`, або створіть **колаційний індекс** (`{ collation: { locale: "en", strength: 2 } }`).

## Вправа 3 — `$text` (повнотекстовий пошук)

### Контекст

Поле пошуку «знайди розробників» має повертати всіх, чий **bio згадує** слово `developer`. Поле bio достатньо «текстуальне», тож хочемо стемінг та коректні межі слів (щоб `developer`, `developers`, `developing` пов'язувалися) і швидкість — тобто індекс.

### Чого ви навчитеся

- Оператору `$text` і параметру `$search`.
- Чому `$text` **обов'язково** потребує текстового індексу на полі.
- Чим `$text` відрізняється від `$regex`: стемінг, межі слів, скоринг.

### Колекція

| Поле | Пошуковий термін | Індекс |
|---|---|---|
| `bio` | `"developer"` | text index `ix_bio_text` |

### Завдання

Знайти всіх, у кого `bio` містить слово `developer` (зі стемінгом), відсортовано за `name`.

### Очікуваний результат

```text
$text (full-text search)
  query={'$text': {'$search': 'developer'}}
  count=2
  docs=[Anna <anna@gmail.com>, Bohdan <bohdan@outlook.com>]
```

(У Anna bio: «Frontend developer and UI engineer». У Bohdan: «Backend developer working with Python».)

### Підказка

`{"$text": {"$search": "developer"}}` — оператор верхнього рівня, не «прив'язаний» до конкретного поля. Потребує текстовий індекс, який створює `coll.create_index([("bio", "text")], name="ix_bio_text")`.

### Розв'язання

```python
coll.create_index([("bio", "text")], name="ix_bio_text")

docs = list(coll.find(
    {"$text": {"$search": "developer"}},
    {"_id": 0},
).sort("name", 1))
```

```javascript
db.string_operators_people.createIndex({ bio: "text" }, { name: "ix_bio_text" })

db.string_operators_people.find(
  { $text: { $search: "developer" } },
  { _id: 0 }
).sort({ name: 1 })
```

### Покрокове пояснення

1. **`$text` — оператор верхнього рівня.** На відміну від `$regex`, який «сидить» під ім'ям поля, `$text` шукає по всіх полях, що включені в текстовий індекс (тут лише `bio`).
2. **Текстовий індекс обов'язковий.** Без нього `$text` кидає `text index required for $text query`. У колекції може бути **не більше одного** текстового індексу (він може покривати кілька полів із вагами).
3. **`$search` токенізує запит** за пробілами, застосовує мовний стемер і прибирає stop-words. Пошук за `"developing"` все одно зіставиться з `"developer"`, бо обидва дають корінь `develop`.
4. **Фразовий пошук** — лапки всередині `$search`: `{"$search": "\"backend developer\""}` зіставляє точну фразу. Поєднання плюс/мінус: `"developer -intern"` виключає документи зі словом `intern`.
5. **Сортування за релевантністю:** додайте `{"score": {"$meta": "textScore"}}` у проєкцію і сортуйте за нею.
6. **`$text` за замовчуванням нечутливий до регістру й діакритики** (конфігурується індексом). `$regex` чутливий, якщо не задати `$options: "i"`.

## Як обирати між `$regex` і `$text`

| Потреба | Оператор |
|---|---|
| Збіг підрядка/шаблону (`@gmail.com$`, `^A`, `\\d+`) | `$regex` |
| Пошук природного тексту за словами (стемінг, stop-words, ранжування) | `$text` |
| Багатомовний стемінг | `$text` з опцією `default_language` |
| Велика колекція, часті пошуки | `$text` (інвертований індекс) |
| Підрядок із лівим якорем | `$regex` з `^` (може взяти btree-індекс) |

---

## Розв'язання типових проблем

| Симптом | Імовірне рішення |
|---|---|
| `$text` повертає `text index required for $text query` | Створіть текстовий індекс: `db.coll.createIndex({ field: "text" })`. |
| `$regex` повільний | Поставте якір `^` і (якщо можна) перенесіть нечутливість до регістру на колаційний індекс. |
| `$regex` збігає більше, ніж очікувалося | Екрануйте regex-мета-символи (`.`, `*`, `+`, `?`) у літеральних підрядках. |
| `$options: "i"` ігнорується | Перевірте, що він в одному dict з `$regex`, а не на верхньому рівні запиту. |
| `$text` зіставляє не той корінь | Дефолтна мова індексу — `english`. Задайте `default_language: "ukrainian"` (або вашу мову) при створенні індексу. |
