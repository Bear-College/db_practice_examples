# Перевірочні оператори у MongoDB (`05_check_operators`)

> Translation / Переклад: [English](../../../../04_mongodb/05_check_operators/check_operators_mongodb.md)

Ці вправи охоплюють **оператори перевірки форми / типу** документа в MongoDB: `$exists`, `$type`, `$mod` і універсальний `$expr` для агрегаційних виразів усередині звичайного `find()`.

Усі приклади виконуються на базі `edu_academy_seed` і колекції **`check_operators_people`**.

Готовий приклад: [`05_check_operators/example.py`](../../../../04_mongodb/05_check_operators/example.py). Він демонструє `$exists` і `$type`. Вправи з `$mod` і `$expr` нижче знято окремо через `mongosh` на тих самих seed-даних.

```bash
pip install -r 04_mongodb/requirements.txt
python 04_mongodb/05_check_operators/example.py
```

Налаштування за замовчуванням:

- `MONGODB_URI=mongodb://localhost:27017`
- `MONGODB_DB=edu_academy_seed`

Seed навмисно змішує BSON-типи у полі `age` (`int`, `double`, `string`), щоб було видно, як `$type` їх розрізняє.

## Карта: оператори перевірки / форми

| Оператор | Призначення | Приклад |
|---|---|---|
| `$exists` | Чи присутнє поле в документі? | `{ phone: { "$exists": true } }` |
| `$type` | Чи є поле саме цього BSON-типу? | `{ age: { "$type": "int" } }` |
| `$mod` | Чи `field % divisor == remainder`? | `{ age: { "$mod": [2, 1] } }` |
| `$expr` | Дозволяє синтаксис агрегаційних виразів (обчислювані поля, `$gt` між двома полями) | `{ "$expr": { "$gt": [ { "$strLenCP": "$phone" }, 15 ] } }` |

## Псевдоніми BSON-типів для `$type`

| Псевдонім | Тип BSON | Літерал у Python |
|---|---|---|
| `"int"` | `Int32` | малий `int` |
| `"long"` | `Int64` | великий `int` (або `bson.Int64`) |
| `"double"` | `Double` | `float` |
| `"decimal"` | `Decimal128` | `bson.Decimal128` |
| `"string"` | `String` | `str` |
| `"bool"` | `Boolean` | `bool` |
| `"date"` | `Date` | `datetime.datetime` |
| `"objectId"` | `ObjectId` | `bson.ObjectId` |
| `"array"` | `Array` | `list` |
| `"object"` | вбудований документ | `dict` |

## Схема колекції

Seed вставляє 5 документів з навмисно змішаними типами і необов'язковим `phone`:

```json
[
  { "name": "Anna",   "age": 17,   "phone": "+1-202-555-0101" },
  { "name": "Bohdan", "age": 18 },
  { "name": "Chris",  "age": 25,   "phone": "+1-202-555-0102" },
  { "name": "Daria",  "age": 30.5, "phone": "+380-44-555-0103" },
  { "name": "Emma",   "age": "45", "phone": "+1-202-555-0104" }
]
```

| Поле | Мікс типів BSON у seed |
|---|---|
| `age` | `Int32` (Anna, Bohdan, Chris), `Double` (Daria), `String` (Emma) |
| `phone` | присутній у всіх **окрім** Bohdan |

## Вправа 1 — `$exists` (наявність поля)

### Контекст

Маркетинг хоче передзвонити клієнтам, у кого є телефон у базі. Документи без поля `phone` треба пропустити.

### Чого ви навчитеся

- Оператору `$exists` з `true` / `false`.
- Різниці між «поле відсутнє» і «поле є, але значення `null`».

### Колекція

| Поле | Предикат |
|---|---|
| `phone` | існує (присутнє у документі) |

### Завдання

Знайти всіх, у чиєму документі **є** поле `phone`, відсортовано за `name`.

### Очікуваний результат

```text
$exists (field exists)
  query={'phone': {'$exists': True}}
  count=4
  docs=[Anna (age=17, phone=+1-202-555-0101, age_type=int), Chris (age=25, phone=+1-202-555-0102, age_type=int), Daria (age=30.5, phone=+380-44-555-0103, age_type=float), Emma (age=45, phone=+1-202-555-0104, age_type=str)]
```

(Bohdan не потрапив — у нього немає поля `phone`.)

### Підказка

`{"phone": {"$exists": True}}` — «присутнє»; `False` — «відсутнє».

### Розв'язання

```python
docs = list(coll.find({"phone": {"$exists": True}}, {"_id": 0}).sort("name", 1))
```

```javascript
db.check_operators_people.find({ phone: { $exists: true } }, { _id: 0 }).sort({ name: 1 })
```

### Покрокове пояснення

1. **`$exists` перевіряє лише наявність ключа** в документі. Поле зі значенням `null` все одно **є** — `$exists: true` його поверне. Щоб шукати «не-null і присутнє», поєднайте з `{phone: {$ne: null}}`.
2. **`$exists: false`** повертає документи, де ключа немає. Корисно для бекфіл-міграцій: «знайти всі рядки, які ще не оброблено».
3. **Індекси:** `$exists: true` іноді ефективно бере sparse / partial-індекс; `$exists: false` — практично ніколи. Для аудиту якості даних на великих колекціях створюйте partial-індекс на потрібне поле.
4. **Колонка `age_type` у вибірці** обчислюється на стороні Python (`type(d["age"]).__name__`). Вона показує, що `$exists` повністю ігнорує BSON-тип значення, тоді як `$type` (наступна вправа) — навпаки, дивиться лише на тип.

## Вправа 2 — `$type` (перевірка BSON-типу)

### Контекст

Аудит якості даних: аналітик очікував, що `age` усюди — чисте ціле, але підозрює мікс типів. Покажіть лише документи, у яких `age` саме BSON `Int32`.

### Чого ви навчитеся

- Фільтру за BSON-типом через `$type`.
- Чому перевірки типу потрібні, коли дані приходять з «брудних» upstream-джерел.

### Колекція

| Поле | Предикат |
|---|---|
| `age` | BSON-тип — `Int32` (псевдонім `"int"`) |

### Завдання

Знайти всіх, у яких `age` — BSON `int`, відсортовано за `name`.

### Очікуваний результат

```text
$type (field type is int)
  query={'age': {'$type': 'int'}}
  count=3
  docs=[Anna (age=17, phone=+1-202-555-0101, age_type=int), Bohdan (age=18, phone=N/A, age_type=int), Chris (age=25, phone=+1-202-555-0102, age_type=int)]
```

(У Daria `30.5` — це `Double`; у Emma `"45"` — це `String`. Обидва виключені.)

### Підказка

`{"age": {"$type": "int"}}` — псевдонім беремо в лапки, не число.

### Розв'язання

```python
docs = list(coll.find({"age": {"$type": "int"}}, {"_id": 0}).sort("name", 1))
```

```javascript
db.check_operators_people.find({ age: { $type: "int" } }, { _id: 0 }).sort({ name: 1 })
```

### Покрокове пояснення

1. **`$type` приймає рядкові псевдоніми або числові коди типу.** Рядки (`"int"`, `"double"`, `"string"`, …) читабельніші; числові коди (1=Double, 2=String, 16=Int32, 18=Int64) — з самої BSON-специфікації.
2. **Масив дозволяє кілька типів:** `{"age": {"$type": ["int", "long"]}}` збігає і `Int32`, і `Int64`. Зручно, коли міграція лишила числові поля у двох розрядностях.
3. **`"number"` — це зручний alias**, що ловить будь-який з `Int32`, `Int64`, `Double`, `Decimal128`. Беріть, коли ширина числа байдужа.
4. **Зв'язок Python ↔ BSON:** Python `int`, що влазить у 32 біти ⇒ `Int32` (псевдонім `"int"`). Більший Python `int` ⇒ `Int64` (псевдонім `"long"`). Python `float` ⇒ `Double`. PyMongo ніколи мовчки не приведе рядок до числа — тому Emma і лишається `"string"`.

## Вправа 3 — `$mod` (арифметика за модулем)

### Контекст

Простий фільтр для адмінки: знайти всіх, у кого **вік — непарний**. Беремо `age % 2 == 1` — `$mod` пакує дільник і залишок в один оператор.

### Чого ви навчитеся

- Оператору `$mod` із масивом `[divisor, remainder]`.
- Чому `$mod` мовчки пропускає не-числові значення.

### Колекція

| Поле | Предикат |
|---|---|
| `age` | `age % 2 == 1` (непарні) |

### Завдання

Знайти всіх, у кого `age` mod `2` дорівнює `1` (непарний вік), відсортовано за `name`.

### Очікуваний результат (знято з `mongosh` наживо)

```text
$mod count=2
[
  { name: 'Anna',  age: 17, phone: '+1-202-555-0101' },
  { name: 'Chris', age: 25, phone: '+1-202-555-0102' }
]
```

(Anna 17 і Chris 25 — непарні. Bohdan 18 — парний. `30.5` у Daria — `Double` і не ціле, `$mod` його пропускає. `"45"` у Emma — рядок, `$mod` не зможе порівняти і теж пропускає.)

### Підказка

`{"age": {"$mod": [2, 1]}}` — двоелементний масив: `[дільник, залишок]`.

### Розв'язання

```python
docs = list(coll.find({"age": {"$mod": [2, 1]}}, {"_id": 0}).sort("name", 1))
```

```javascript
db.check_operators_people.find({ age: { $mod: [2, 1] } }, { _id: 0 }).sort({ name: 1 })
```

### Покрокове пояснення

1. **`$mod` приймає масив із двох елементів.** Будь-що інше дає `BadValue`. Перший — дільник, другий — потрібний залишок.
2. **Не-числові значення пропускаються мовчки.** Рядкове значення Emma **не** кидає помилку — Mongo просто повертає «не збігається» для цього документа. Тому аудит даних варто комбінувати `$mod` із `$type`, щоб знати, скільки документів випало з фільтра.
3. **Пастка з float:** `{"age": {"$mod": [2, 0]}}` на `Double` 30.5 дає false (`30.5 % 2 == 0.5`). `$mod` поважає арифметику з плаваючою крапкою — для «лише цілих» спочатку обмежте `{"age": {"$type": "int"}}`.
4. **Індекси:** `$mod` не індексо-дружній. Планувальник мусить читати кожне значення і рахувати залишок. Тримайте як вторинний предикат, не як основний фільтр.

## Вправа 4 — `$expr` (порівняння через обчислювані вирази)

### Контекст

Аудитуємо телефони і шукаємо всі документи, де **збережений телефон довший за 15 символів** (натяк на код країни чи розширення). Простий `$eq`/`$gt` на значенні не підійде — треба порівняти **довжину** поля, а не його значення.

### Чого ви навчитеся

- Оператору `$expr`, який «піднімає» агрегаційні вирази у мову запитів.
- Обчисленням на значенні поля через `$strLenCP`, `$ifNull` тощо.
- Посиланням на поля через `$` (`"$phone"`) усередині `$expr`.

### Колекція

| Поле | Предикат |
|---|---|
| `phone` | `strLenCP(phone) > 15` |

### Завдання

Знайти всіх, у кого рядок `phone` **довший за 15 символів**, відсортовано за `name`.

### Очікуваний результат (знято з `mongosh` наживо)

```text
$expr strLen > 15 count=1
[
  { name: 'Daria', age: 30.5, phone: '+380-44-555-0103' }
]
```

(Усі чотири телефони у seed мають довжину 15 (`+1-202-555-0101`-формат) або 16 (UA-формат Daria). Лише 16-символьний телефон Daria проходить строге `> 15`.)

### Підказка

`{"$expr": {"$gt": [{"$strLenCP": {"$ifNull": ["$phone", ""]}}, 15]}}` — у `$expr` можна писати вираз, що звертається до поля з префіксом `$`.

### Розв'язання

```python
docs = list(coll.find(
    {
        "$expr": {
            "$gt": [
                {"$strLenCP": {"$ifNull": ["$phone", ""]}},
                15,
            ]
        }
    },
    {"_id": 0},
).sort("name", 1))
```

```javascript
db.check_operators_people.find(
  {
    $expr: {
      $gt: [
        { $strLenCP: { $ifNull: ["$phone", ""] } },
        15
      ]
    }
  },
  { _id: 0 }
).sort({ name: 1 })
```

### Покрокове пояснення

1. **`$expr` перемикає парсер у режим агрегаційних виразів.** Усередині `$gt` — це *агрегаційний* `$gt` (функція з масивом `[a, b]`), а не *запитовий* `$gt` (єдиний операнд до поля).
2. **Посилання на поля через `"$phone"`.** Префікс `$` означає «значення поля `phone` цього документа». Без `$` ви б порівнювали з літеральним рядком `"phone"`.
3. **`$ifNull: ["$phone", ""]`** прикриває документи без поля (Bohdan). Без нього `$strLenCP` від відсутнього поля впав би або повернув null. Запасне `""` робить «довжину» Bohdan нулем — це нижче за 15, тож він коректно виключений.
4. **`$strLenCP`** рахує Unicode code points (правильно для більшості мов). `$strLenBytes` рахує UTF-8 байти — для не-ASCII це інше число.
5. **Коли обирати `$expr`, а не звичайні query-оператори:**
   - Треба порівняти **два поля одного документа** (`$expr: { $gt: ["$created_at", "$updated_at"] }`).
   - Треба **щось обчислити** з поля (довжина, рік дати, сума масиву).
   - Треба агрегаційні оператори (`$cond`, `$switch`, `$concat`, …) усередині `find()`.
   - Для звичайного `поле <op> константа` беріть прості query-оператори; `$expr` має більший парсинг-оверхед.

## Розв'язання типових проблем

| Симптом | Імовірне рішення |
|---|---|
| `$exists: true` повертає документи зі значенням `null` | Так і має бути — `null` це «присутнє». Поєднайте з `$ne: null`, якщо треба «не-null». |
| `$type: "int"` пропускає схожі на цілі значення | Це або `Double` (`30.0`), або `String` (`"30"`). Беріть `$type: ["int", "long", "double"]` або `$type: "number"`. |
| `$mod` нічого не повертає на «очевидному» документі | Поле зберігається як рядок чи має дробову частину — обмежте через `$type: "int"`. |
| `$expr` скаржиться на ім'я поля з `$` | Ви забули знак долара — без нього Mongo вважає значення літералом. |
| `$expr` ігнорує мій предикат | Усередині `$expr` беріть агрегаційні `$gt`/`$lt` з масивами, **а не** query-стиль `{ $gt: 5 }`. |
